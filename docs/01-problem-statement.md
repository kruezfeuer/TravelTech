# Описание проблемы

## Контекст

Путешествие обычно состоит из нескольких взаимосвязанных элементов: перелёта, проживания, трансфера, активности и дополнительных бронирований. При изменении одного из элементов, особенно рейса, весь план поездки может стать неактуальным.

Пользователь ожидает, что сервис будет отслеживать изменения рейсов, уведомлять о задержках и отменах, а также предлагать подходящие альтернативы без необходимости вручную пересобирать маршрут.

---

## Проблема

Существующие сценарии планирования поездки требуют работы с несколькими внешними сервисами и разрозненными подтверждениями бронирований. Это приводит к следующим трудностям:

- пользователь теряет целостную картину поездки;
- изменения рейса приходят с задержкой и не всегда синхронно отражаются в общем плане;
- альтернативы приходится подбирать вручную;
- в групповой поездке участники могут видеть разные версии маршрута;
- офлайн-режим и разные тайм-зоны усложняют согласование изменений;
- паспортные и другие персональные данные требуют строгого контроля срока хранения.

---

## Цель проекта

Создать сервис планирования путешествий, который:

- объединяет бронирования и расписания в едином интерфейсе;
- отслеживает статус рейсов через внешние источники;
- уведомляет пользователя о задержках и отменах;
- предлагает альтернативные рейсы, трансферы, отели или активности;
- обновляет общий план поездки;
- поддерживает групповой режим и офлайн-синхронизацию;
- ограничивает хранение паспортных данных сроком, необходимым для поездки.

---

## Бизнес-ценность

Реализация сервиса позволит:

- сократить время планирования поездки;
- снизить количество ручных действий;
- уменьшить риск пропустить изменение рейса;
- повысить удобство групповых путешествий;
- улучшить качество рекомендаций и повторных поездок;
- обеспечить контроль над чувствительными данными.

---

## Критерии успеха

Проект считается успешным, если:

- пользователь может создать поездку и добавить в неё элементы маршрута;
- система получает изменения статуса рейса из внешних источников;
- при задержке или отмене рейса пользователь получает уведомление;
- система предлагает хотя бы одну релевантную альтернативу, если она существует;
- общий план поездки обновляется согласованно;
- участники группы видят одну и ту же актуальную версию маршрута;
- паспортные данные не хранятся дольше необходимого срока.

---

## Ограничения

В рамках MVP:

- поддерживается один активный план поездки для группы;
- интеграции реализуются только через заранее определённые внешние API;
- статус рейса приходит с возможной задержкой;
- пользователь может быть офлайн;
- персонализация ограничена доступными данными профиля и истории поездок;
- паспортные данные используются только для целей бронирования и проверки ограничений.

---

## Не входит в текущий объём

- полная туристическая страховка;
- оформление виз;
- возврат средств за все типы бронирований;
- интеграция со всеми существующими поставщиками;
- сложные программы лояльности;
- чат между участниками поездки.
