# Функциональные требования

## 1. Назначение документа

Документ описывает функциональные требования к сервису планирования путешествий.

---

## 2. Поездка и участники

| ID | Требование |
|---|---|
| FR-001 | Система должна позволять создавать поездку с названием, датами, направлением и временной зоной. |
| FR-002 | Система должна позволять добавлять и удалять участников поездки. |
| FR-003 | Система должна поддерживать права доступа для владельца поездки и участников группы. |
| FR-004 | Система должна хранить текущую версию плана поездки. |

---

## 3. Поиск и бронирования

| ID | Требование |
|---|---|
| FR-005 | Система должна поддерживать поиск перелётов, отелей, трансферов и активностей через внешние API. |
| FR-006 | Система должна предоставлять фильтрацию результатов поиска. |
| FR-007 | Система должна позволять бронировать выбранный вариант и сохранять результат бронирования. |
| FR-008 | Система должна связывать бронирования с поездкой и конкретным сегментом маршрута. |
| FR-009 | Система должна поддерживать повторный запрос без создания дубликатов при наличии идемпотентного ключа. |

---

## 4. Мониторинг рейсов и уведомления

| ID | Требование |
|---|---|
| FR-010 | Система должна получать обновления статуса рейса из внешних источников. |
| FR-011 | Система должна сопоставлять обновления с конкретной поездкой и сегментом маршрута. |
| FR-012 | Система должна уведомлять пользователя о задержке, отмене или существенном изменении рейса. |
| FR-013 | Система должна хранить историю событий по рейсу и уведомлениям. |

---

## 5. Альтернативы и обновление плана

| ID | Требование |
|---|---|
| FR-014 | Система должна предлагать альтернативные рейсы, отели, трансферы или активности при изменении маршрута. |
| FR-015 | Система должна учитывать багаж, визовые ограничения и временные зоны при формировании альтернатив. |
| FR-016 | Система должна позволять принять, отклонить или отложить предложенную альтернативу. |
| FR-017 | Система должна обновлять общий план поездки после подтверждения изменения. |
| FR-018 | Система должна сохранять версии плана поездки после каждого существенного изменения. |

---

## 6. Групповая работа и синхронизация

| ID | Требование |
|---|---|
| FR-019 | Система должна поддерживать групповой режим поездки. |
| FR-020 | Система должна показывать актуальное состояние поездки всем участникам с соответствующими правами. |
| FR-021 | Система должна фиксировать согласование или отклонение изменений участниками группы. |
| FR-022 | Система должна синхронизировать изменения после восстановления связи. |

---

## 7. Офлайн-режим и персональные данные

| ID | Требование |
|---|---|
| FR-023 | Система должна сохранять локальные изменения при отсутствии сети. |
| FR-024 | Система должна передавать накопленные изменения после восстановления связи. |
| FR-025 | Система должна минимизировать хранение паспортных данных и удалять их после истечения необходимого срока. |
| FR-026 | Система должна позволять использовать паспортные данные только для бронирования и проверки ограничений. |
