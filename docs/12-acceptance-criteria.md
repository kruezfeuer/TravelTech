# Критерии приёмки

## 1. Назначение документа

Документ определяет проверяемые критерии, по которым оценивается готовность сервиса планирования путешествий.

---

## 2. Критерии приёмки

### AC-01. Создание поездки

**Given** пользователь авторизован  
**When** он создаёт новую поездку  
**Then** система сохраняет поездку и возвращает её идентификатор

### AC-02. Добавление участника

**Given** поездка существует  
**When** пользователь добавляет участника  
**Then** участник связывается с поездкой и получает доступ по заданной роли

### AC-03. Поиск вариантов

**Given** пользователь ввёл параметры поиска  
**When** система обращается к внешнему API  
**Then** пользователь получает список подходящих вариантов

### AC-04. Бронирование

**Given** пользователь выбрал вариант  
**When** он подтверждает бронирование  
**Then** система сохраняет бронирование и привязывает его к поездке

### AC-05. Уведомление о задержке рейса

**Given** внешний источник сообщил о задержке  
**When** система сопоставила событие с поездкой  
**Then** пользователь и участники получают уведомление

### AC-06. Предложение альтернативы

**Given** рейс задержан или отменён  
**When** система формирует альтернативы  
**Then** пользователю показываются только варианты, соответствующие ограничениям

### AC-07. Обновление маршрута

**Given** пользователь выбрал альтернативу  
**When** он подтверждает изменение  
**Then** маршрут обновляется и сохраняется новая версия поездки

### AC-08. Групповая поездка

**Given** поездка создана в групповом режиме  
**When** участники просматривают маршрут  
**Then** они видят одну актуальную версию плана

### AC-09. Конфликт правок

**Given** два участника изменили один и тот же участок плана  
**When** система обнаружила конфликт  
**Then** она не перезаписывает данные без явного разрешения конфликта

### AC-10. Офлайн-режим

**Given** пользователь был офлайн  
**When** связь восстановилась  
**Then** локальные изменения синхронизируются или переводятся в состояние конфликта

### AC-11. Контроль хранения паспортных данных

**Given** срок хранения паспортных данных истёк  
**When** выполняется очистка  
**Then** данные удаляются или обезличиваются и больше не используются

### AC-12. Тайм-зоны

**Given** сегменты поездки находятся в разных часовых поясах  
**When** система рассчитывает пересадки  
**Then** время отображается и сравнивается корректно с учётом тайм-зон

---

## 3. Критерии готовности кейса

Кейс считается достаточным для портфолио, если:

- есть согласованные docs 01–12;
- есть context, state, sequence, BPMN, ERD и architecture;
- структура артефактов единообразна;
- Mermaid и drawio-диаграммы совпадают по смыслу;
- в документах явно отражены групповой режим, офлайн и ограничения по персональным данным.
