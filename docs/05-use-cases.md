## 3. UC-01. Создать поездку

### Цель
Создать новую поездку с основными параметрами.

### Предусловия
Пользователь авторизован.

### Основной сценарий
1. Пользователь создаёт новую поездку.
2. Сервис запрашивает название, даты, направление и временную зону.
3. Пользователь вводит данные.
4. Сервис сохраняет поездку и возвращает карточку поездки.

### Результат
Создана запись о поездке.

---

## 4. UC-02. Добавить участника в поездку

### Цель
Добавить участника в совместную поездку.

### Основной сценарий
1. Пользователь открывает поездку.
2. Пользователь добавляет участника.
3. Сервис создаёт связь участника с поездкой.
4. Участник получает приглашение или доступ по правилам системы.

### Альтернативы
- участник уже существует;
- приглашение не доставлено;
- у участника нет прав на редактирование.

---

## 5. UC-03. Найти и выбрать элемент поездки

### Цель
Найти перелёт, отель, трансфер или активность.

### Основной сценарий
1. Пользователь выбирает тип элемента.
2. Сервис обращается к внешнему API.
3. Сервис возвращает доступные варианты.
4. Пользователь применяет фильтры.
5. Пользователь выбирает вариант.

---

## 6. UC-04. Забронировать выбранный вариант

### Цель
Создать бронирование и привязать его к поездке.

### Основной сценарий
1. Пользователь подтверждает выбранный вариант.
2. Сервис проверяет доступность и ограничения.
3. Сервис отправляет запрос на бронирование.
4. Сервис сохраняет результат бронирования.
5. Сервис добавляет элемент в маршрут поездки.

---

## 7. UC-05. Получить уведомление об изменении рейса

### Цель
Уведомить пользователя о задержке или отмене.

### Основной сценарий
1. Внешний источник передаёт новый статус рейса.
2. Сервис сопоставляет его с поездкой.
3. Сервис создаёт уведомление.
4. Пользователь получает push или in-app сообщение.

---

## 8. UC-06. Предложить альтернативу

### Цель
Сформировать подходящие альтернативные варианты при изменении рейса.

### Основной сценарий
1. Сервис определяет затронутые сегменты поездки.
2. Сервис проверяет ограничения по багажу, визам и времени.
3. Сервис запрашивает внешние источники.
4. Сервис возвращает список альтернатив.
5. Пользователь выбирает новую опцию или отклоняет предложения.

---

## 9. UC-07. Обновить общий план поездки

### Цель
Согласованно обновить маршрут после выбора альтернативы.

### Основной сценарий
1. Пользователь или группа подтверждают изменение.
2. Сервис обновляет затронутые сегменты.
3. Сервис сохраняет новую версию плана.
4. Все участники видят актуальную версию.

---

## 10. UC-08. Синхронизировать изменения после офлайна

### Цель
Применить локальные изменения после восстановления связи.

### Основной сценарий
1. Пользователь вносит изменения без интернета.
2. Сервис сохраняет их локально.
3. После восстановления связи выполняется синхронизация.
4. Система проверяет конфликты.
5. Изменения либо применяются, либо переводятся в состояние согласования.
